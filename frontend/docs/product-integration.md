## Initial findings, before implementation

Authentication already used Django session cookies, CSRF bootstrap/rotation, OTP request/verification, session restoration, role guards, logout, sanitized errors, and cooldowns. Student OTP eligibility and association are enforced in backend institutional records; no new registration or claiming flow is needed.

The live student boundary always rendered an integration-pending screen. Demo student pages consume `data/mock.ts`; demo administrator pages consume `admin/mock.ts` through `AdminWorkspace`. Administrator service mutations were intentionally unavailable. Live admin access was blocked because the older `/accounts/me/` response omitted capabilities. Public PDF verification had a guarded transport, but passport-reference lookup returned a hardcoded endpoint-missing failure. A public selector still offered standalone credential lookup.

The checked-out Django URL configuration does not include `apps.api`; checked-out passport views are empty. Its student-profile route requires an external student identifier that the session response does not expose. Guessing that identifier from an email would be unsafe. Its public verification and Classroom sources are simulated. These facts prevent a working full product against this checkout alone.

## Implemented frontend changes

Live routes mount a dedicated workspace using the existing sidebar, card, button, and layout styles. Demo routes retain their existing components and fixtures. Live navigation contains the supported product actions; game and other placeholder routes are omitted from its navigation. The live home route opens public verification, with student and administrator sign-in links in its header.

Student dashboard/profile, recognized skills, achievements, credentials, passport, PDF preparation/status/download, and share-link actions call the inspected integration APIs. A missing passport is an explicit empty state, not a missing-service error. Sharing includes only the public passport reference. PDF readiness comes from backend metadata, with polling only while pending/generating; downloads require an actual PDF binary response.

Administrator access consumes the integration backend's explicit `capabilities` array. Missing capabilities retain the closed older-backend behavior. Django continues to authorize every request. Statistics, paginated student and credential records, student passport reads, achievement-based issuance, reasoned credential revocation, Excel/server-configured Google Sheets imports, and persisted import/sync history have live adapters. Issuance preserves its idempotency key when a failed request is retried without changing the selection. Credential revocation delegates passport lifecycle changes to existing backend services; no separate passport-revocation route was invented.

Classroom currently declares a simulated source even on the inspected integration revision. The UI offers a clearly labeled preview and history; live synchronization remains a backend connector blocker. Import responses display returned counts and persisted history, never a locally generated success result.

Public verification offers passports and original PDFs, with no standalone credential selector or credential QR journey. It accepts a public passport UUID, printed `passport:UUID` / `passport-version:UUID`, or the same-origin share URL generated by this frontend. QR links prefill a reference and require explicit submission. Arbitrary URLs are never fetched. The credential verification backend and its security are unchanged.

Public results allowlist only registry source and version metadata. Revoked/expired records can still be authentic historical documents; these conditions are preserved rather than mistaken for malformed responses or successful validity. Unknown pending/failed statuses fail closed as unsupported responses. Blockchain proof is explicitly unavailable when absent from the contract; registry validity is never labeled a successful blockchain check.

## Confirmed API contracts

All private paths below are relative to same-origin `/api/`, use the existing session client, and obtain CSRF for writes.

- `accounts/csrf/`, `accounts/otp/request/`, `accounts/otp/verify/`, `accounts/login/`, `accounts/me/`, `accounts/logout/`: existing authentication contracts. Integration `/me/` additionally supplies capability names, not arbitrary permission objects.
- `GET student/dashboard/`: profile, recognized skill/achievement counts, credential counts, recent achievements/credentials, and optional passport.
- `GET student/skills/`, `student/achievements/`, `student/credentials/`: DRF numbered pagination (`count`, `next`, `results`).
- `GET student/passport/`: passport object or exactly the no-passport indicator `passport: null`.
- `POST student/passport/pdf/`: empty JSON object; `GET .../pdf/status/`: status and `available_for_download`; `GET .../pdf/download/`: authorized PDF binary. Admin equivalents are under `admin/passports/<id>/pdf/`.
- `GET admin/statistics/`, `admin/students/`, `admin/students/<id>/`, `admin/students/<id>/achievements/`, `admin/passports/?student_id=<id>`, `admin/credentials/`: protected reads. Lists use numbered pagination.
- `POST admin/credentials/issue/`: `achievement_ids` and `idempotency_key`. `POST admin/credentials/<id>/revoke/`: `reason`.
- `POST integrations/import/excel/`: multipart `file`; `POST integrations/import/google-sheets/`: empty object, server-configured source only. `GET integrations/imports/` and `integrations/classroom/events/`: cursor pagination. Pagination extracts only the cursor and reuses the original trusted path.
- `POST integrations/classroom/sync/`: preview uses `dry_run: true`. No live synchronization from this UI while source provenance remains simulated.
- Public, cookie-free requests: `GET verification/passport/<UUID>/`, `GET verification/passport-version/<UUID>/`, `POST verification/document/` with multipart `file`. The printed prefix is normalized before routing.

Public verification remains explicitly deployment-gated. For a confirmed integration backend, set `VITE_PUBLIC_VERIFICATION_ENABLED=true` and approve `POSTGRESQL_PASSPORT_REGISTRY,POSTGRESQL_DOCUMENT_REGISTRY` in `VITE_PUBLIC_VERIFICATION_SOURCES`. Never approve a simulated source. Production must route same-origin `/api/` to Django; the Vite development proxy targets `127.0.0.1:8000`.

## Exact service end-to-end acceptance journey

Use a disposable database/storage namespace and synthetic institutional accounts. Verify the administrator has only the capabilities needed for the test.

1. Administrator signs in with email/password, reloads, and remains signed in through the server session. Confirm private lists/statistics are authorized.
2. Import a synthetic `.xlsx` completion from an approved source (or synchronize once an authorized real Classroom connector exists). Inspect persisted run outcomes and avoid duplicate issuance on replay.
3. Select that student's recognized achievement and issue a credential with an idempotency key. Confirm persisted credential and passport/version changes. Also test automatic issuance from an approved completion if configured.
4. Sign out. Request an OTP for the pre-existing synthetic university record, consume the delivered OTP, reload, and verify ownership of profile/skills/credentials/passport. No user-supplied student identifier may establish ownership.
5. Prepare the passport PDF, observe pending/generating/issued or failure metadata, download the real stored binary, and copy the public link.
6. In an anonymous browser context, submit the shared reference, its printed version reference/QR link, and original PDF. Confirm exact statuses and absence of private student/account data in responses.
7. Check the blockchain proof through the integrated service, then repeat with pending, failed, and unavailable providers. Registry validity alone must not satisfy this step.
8. Revoke the credential with a reason; verify persisted audit/lifecycle outcomes and public revocation of the affected passport. Repeat with expired credentials and an outdated passport version.
9. Test a linked student without a passport, another student's identifiers, an administrator without each required capability, anonymous private reads/writes, invalid/expired/reused OTP, session expiry, failed logout, missing routes, rate limits, backend failures, and network interruption during issuance/import/PDF generation.
